# Nateks Monitoring — журнал решений и экспериментов

Этот файл ведётся автоматически в процессе работы над проектом. Пользователь не должен вручную переносить сюда результаты. Перед продолжением работы сначала проверять журнал.

## Правила записи
- Записывать существенные эксперименты, решения и изменения состояния задачи.
- Для SNMP сохранять команду, полный OID, фактический ответ и статус.
- Ошибки `Timeout`, `No Such Object` и другие неудачные проверки сохранять, чтобы не повторять их без причины.
- Разделять факт, гипотезу и принятое решение.
- После каждого существенного результата указывать следующий шаг.

## 2026-10-26 — адаптация NXI-3050 и LLDP

### Цель
Адаптировать мониторинг NXI-3030 Legacy под NXI-3050 так, чтобы в Zabbix достоверно отображались LLDP-соседи: локальный порт, удалённое устройство, IP и удалённый порт. До завершения настройки Zabbix не менять `app.js`.

### Подтверждено на NXI-3050 (10.0.110.10)
- SNMP v2c с параметрами из тестов работает для vendor subtree `1.3.6.1.4.1.4249`.
- `snmpwalk -v2c -c pubsheksna -t 3 -r 0 10.0.110.10 1.3.6.1.4.1.4249` возвращает значения из vendor-таблиц, включая:
  - `1.3.6.1.4.1.4249.1.201.1.4.1.1.1.2.*` — значения вида `50659585`, `33686017` и т. п.; используется как источник IFINDEX в текущем исследовании.
  - `1.3.6.1.4.1.4249.1.201.1.4.1.1.1.4.1.1 = INTEGER: 1` и аналогичные записи — столбец отвечает при ручном индексировании.
  - `1.3.6.1.4.1.4249.1.201.1.4.1.1.1.1.*` содержит записи по портам 1–7 с конечными индексами 1–4.
- Полный walk vendor subtree в текущем тесте завершился `Timeout` после части вывода. Это не доказывает отсутствие остальных объектов.
- Web UI NXI-3050 показывает LLDP-соседей. Зафиксированный пример: локальный `Port_1/2`, удалённый `Port_9`, IP `10.0.110.18`, имя `sw-3030-kp-0km`, описание `NetXpertNXI-3030`. Страница `/ShowLldpPage` была получена через `curl --http0.9` с авторизацией/cookie.

### Проверки LLDP через SNMP
- `1.0.8802.1.1.2.1.4.1.1.9` → `No Such Object available on this agent at this OID`.
- `1.0.8802.1.1.2.1.4.1.1.7` → `Timeout`.
- `1.0.8802.1.1.2.1.4.1.1.8` → `Timeout`.
- `1.0.8802.1.1.2.1.4.2.1.3` → `Timeout`.
- `1.3.6.1.4.1.4249.1.201.15.1.1.1.1.1.1.1` → `Timeout`.

Вывод: перечисленные OID пока не считать рабочими источниками LLDP для NXI-3050.

### Важные решения
- Не менять `app.js` до стабильного получения LLDP в Zabbix.
- `Bridge Ports Discovery` не использовать как способ получения LLDP; его назначение в текущем шаблоне связано с bridge/VLAN и сопоставлением портов.
- Не создавать новое LLD только из-за проблем с текущим discovery. Сначала определить, какие существующие элементы шаблона можно адаптировать.
- Не заменять весь шаблон целиком. Менять только подтверждённые OID/параметры.

### Следующий шаг
Продолжить поиск LLDP OID на NXI-3050 узкими SNMP-запросами, используя уже подтверждённые части vendor subtree и не повторяя перечисленные нерабочие проверки без новой причины.
