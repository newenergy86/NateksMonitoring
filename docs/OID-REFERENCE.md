# OID Reference — NetXpert NXI-3050

Справочник разделяет подтверждённые OID и неподтверждённые гипотезы. Обозначение «отвечает» не означает, что семантика объекта окончательно установлена.

## Подтверждённые SNMP OID
| OID / префикс | Что известно | Уровень подтверждения |
|---|---|---|
| `1.3.6.1.4.1.4249.1.201.1.4.1.1.1.2` | Таблица возвращает целые значения вида 50659585, 33686017 и т. п., использовалась в LLD как `{#IFINDEX}` | Ответ SNMP подтверждён; трактовку значения надо учитывать как vendor IFINDEX |
| `1.3.6.1.4.1.4249.1.201.1.4.1.1.1.4` | Запрос по столбцу и ручным индексам вида `.1.1` давал Integer: 1 | Часть OID отвечает; название/семантика столбца требует проверки |
| `1.3.6.1.4.1.4249.1.201.1.4.1.1.1.8` | В предыдущем SNMP дампе были значения с индексами `<port>.<subindex>`, например 4 для первых портов и 2 для следующих | Значения зафиксированы ранее; повторный тест может требоваться, если устройство/конфигурация изменилась |
| `1.3.6.1.4.1.4249.1.201.1.9.1.30.0` | В сохранённом дампе: `STRING: "NetXpert NXI-3050"` | Подтверждено сохранённым SNMP дампом |

## LLDP: пока не подтверждено через SNMP
| OID / префикс | Результат | Вывод |
|---|---|---|
| `1.0.8802.1.1.2.1.4.1.1.7` | `Timeout` | Не считать рабочим пока не будет повторно проверен |
| `1.0.8802.1.1.2.1.4.1.1.8` | `Timeout` | Не считать рабочим пока не будет повторно проверен |
| `1.0.8802.1.1.2.1.4.1.1.9` | `No Such Object` | Конкретный объект не доступен по этому OID на момент теста |
| `1.0.8802.1.1.2.1.4.1` | `Timeout` | Большой subtree не вернул таблицу |
| `1.3.6.1.4.1.4249.1.201.15.1.1.1.1` | При запросе `...1.1.1.1.1.1` был `Timeout` | OID из шаблона NXI-3030; для NXI-3050 не подтверждён |

## Другой достоверный канал LLDP
Web UI NXI-3050, страница `/ShowLldpPage`, отдаёт LLDP HTML. Для запроса использовался `curl --http0.9` с авторизацией и cookie token. Пример записи:
- Local Port ID: `Port_1/2`
- Remote Port ID: `Port_9`
- Remote Management Address: `10.0.110.18`
- Remote System Name: `sw-3030-kp-0km`
- Remote System Description: `NetXpertNXI-3030`

Эти данные подтверждают наличие LLDP-соседей, но не доказывают наличие конкретного LLDP OID в SNMP.

## Важно
Не считать vendor OID `4249.1.201.15...` рабочим на 3050 только потому, что он присутствует в шаблоне 3030. Не менять OID в живом Zabbix без одного успешного GET/WALK и сверки результата с Web UI.
